# 「动捕棚」文章系统：改造计划

> 日期：2026-10-20 · 状态：待确认
> 目标：把 design-lab 里手写的 B 版文章，变成「AI 写 Markdown → 生成器自动出页面 → 一键导出 CSDN」的可复用系统。

## 0. 核心原则：不做死模板，做「设计系统 + 写作 skill」

用户的要求是：文章以后主要交给 AI 输出，不要很硬、很死的模板。所以系统分三层，越往下越固定、越往上越自由：

| 层 | 内容 | 谁来改 | 自由度 |
|---|---|---|---|
| **写作层** | 每篇文章的 Markdown、文章专属的交互组件 | AI（按 skill 指引） | 高：每篇可以有自己的首屏和组件 |
| **组件库** | 三角测量、流水线、失败日志、考试…… 可复用组件 | AI 或人，沉淀出来的组件 | 中：遵守组件契约即可 |
| **设计系统** | 色彩 / 字体 token、版式外壳、动效原语、阅读体验 | 人工把关 | 低：保证全站一致 |

**关键设计：文章可以自带组件。**文章可以是一个文件夹（`content/docs/<slug>/index.md` + `widgets.js` + 图片），生成器会自动加载这个文件夹里的组件。AI 遇到需要新交互的文章时，直接为这篇写一个专属组件，不需要改模板，也不需要改生成器。好用的专属组件以后再「晋升」进组件库。

## 1. Phase 0 — B 版动效升级（先在 design-lab 迭代审美）

在动工生成器之前，先把动效做到满意，因为动效原语会直接进入设计系统。所有动效都贴合「动捕棚」的隐喻，而不是通用的淡入：

| # | 动效 | 隐喻 | 作用位置 |
|---|---|---|---|
| M1 | **标记点成形**：标题每个字先是一个荧光标记点，再「长」成字形，逐字错开 | 动捕标记 → 实体 | 首屏标题、章节标题 |
| M2 | **时间码滚动**：章节时间码从 `00:00:00` 滚到目标值，数字逐位锁定 | 对视频 | 章节头 |
| M3 | **对焦**：章节标题由模糊、轻微放大变清晰 | 相机对焦 | 章节头 |
| M4 | **扫描线擦除**：段落进入视口时，一条荧光扫描线从左到右扫过，文字随之显现（只做一次，克制） | 扫描仪 | 首段、引用 |
| M5 | **荧光笔划线**：`<b>` 重点词的下划线在进入视口时画出来 | 标记 | 正文重点 |
| M6 | **取景框锁定**：组件外框四角的取景角标从外向内收拢、锁定，伴随一次 REC 闪烁 | 取景器 | 所有交互组件 |
| M7 | **镜头推拉**：滚动时首屏取景器轻微缩放并变暗，正文像从画面里推出来 | 推轨镜头 | 首屏（滚动驱动） |
| M8 | **追踪括号**：引用句的重点词四周出现追踪框，锁定后变色 | 目标跟踪 | 大字引用 |
| M9 | **数字滚动**：遥测数字从 0 计数到目标值 | 仪表读数 | 数据卡 |
| M10 | **章节轨刻度**：左侧时间码轨每一节下方有一条细进度条，读到哪里亮到哪里 | 时间线 | 左侧目录 |

技术约束（写进设计系统）：
- 只动 `transform` / `opacity` / `clip-path` / `filter`，不触发重排；
- 优先用 CSS 滚动驱动动画（`animation-timeline: view()`），不支持的浏览器回退到 IntersectionObserver；
- `prefers-reduced-motion` 下全部降级为静态，内容不受影响；
- 动效只播一次，不打断阅读；正文段落的动效时长 ≤ 600ms。

**交付**：升级后的 `design-lab/b-stage.html`。你确认审美后再进入 Phase 1。

## 2. Phase 1 — 抽取设计系统

```
static/stage/
├── stage.css          # token + 版式外壳（顶栏 / 首屏 / 时间码轨 / 正文 / 模块外壳）
├── motion.js          # M1–M10 动效原语，按 data-motion 属性自动挂载
├── runtime.js         # 入口：扫描 [data-widget] → 按名字动态 import 对应组件
├── creature.js        # 四足 FK（从 design-lab 迁移）
└── widgets/           # 组件库：每个组件一个文件，按需加载
    ├── triangulation.js  pipeline.js  methods.js
    └── rig-select.js  synth-data.js  exam.js  depth-duel.js
```

- 组件**按需动态加载**：页面用到哪个组件才下载哪个文件，不会因为组件库变大拖慢每一页。
- 组件契约统一：`export function mount(root, ctx)`；`ctx` 提供 `props`（来自 Markdown）、`onceVisible`、`whileVisible`、`reduceMotion`；颜色只读 CSS 变量。
- 首屏也是组件：frontmatter 写 `hero: mocap-gait`（默认）或文章专属的首屏组件名。

## 3. Phase 2 — 生成器改造（全部带测试）

| 改动 | 说明 |
|---|---|
| `design: stage` 选择版式 | frontmatter 有 `design: stage` 的文章用新外壳；**旧文章（含 CSDN 导入的 HTML 文章、日报）完全不受影响** |
| `::: interactive <名字> {props}` 指令 | 渲染为 `<div data-widget>`，块内 Markdown 渲染成降级内容放在里面：组件挂载后隐藏，没有 JS 时照样能读、能被搜索引擎收录 |
| 标题时间码 | `## [01:20] 标题` 自动拆成时间码标签 + 标题，并进入左侧目录；没有时间码的标题也可以写 `## [NOTE] 标题` |
| 自动目录 | 从所有 `##` 生成左侧时间码轨 |
| 文件夹文章 | 支持 `content/<板块>/<slug>/index.md`；同文件夹的 `widgets.js`、图片会被复制到 `public/<板块>/<slug>/`，页面自动加载 |
| 重点句 / 账本等写作块 | `::: quote`、`::: ledger`、`::: lessons` 等少量语义块，对应 B 版里的大字引用、结果账本、方法论列表 |
| 静态资源 | `static/stage/` 随现有的 `copy_static()` 一起部署（上次已修好子目录复制） |

测试：指令解析（嵌套、属性、未闭合时报错）、降级内容、时间码标题、目录生成、文件夹文章的资源复制、旧文章渲染结果不变（快照比对）。

## 4. Phase 3 — CSDN 导出适配

- `::: interactive` 块 → 展开成块内的降级内容，后面追加一行「▶ 交互演示见原文：<链接>#<锚点>」；
- `## [01:20] 标题` → 普通标题，保留时间码文字；
- 语义块 → 普通 Markdown（引用、列表）。
- 测试：导出结果不含任何 `:::`，所有交互块都有原文锚点链接。

## 5. Phase 4 — 写作 skill（给 AI 用的「活模板」）

位置：`blog/.claude/skills/stage-article/`（跟仓库一起走，组件更新时 skill 同步更新）

```
stage-article/
├── SKILL.md                 # 触发条件 + 完整工作流
└── references/
    ├── writing.md           # 文章范式：结论先行、问题→尝试→化简→方案→验证→局限→方法论
    ├── components.md        # 组件库目录：每个组件的用途、props、降级写法、示例
    ├── widget-contract.md   # 写专属组件的契约、主题变量、无障碍、性能要求
    ├── motion.md            # 动效原语清单和使用分寸（哪里用、哪里克制）
    └── qa.md                # 自检清单：1440 / 375 截图、控制台、reduced-motion、事实与「示意」标注
```

SKILL.md 的工作流：
1. **取材**：视频 → 抓字幕；文章 / 论文 → 读全文。只从原文取事实。
2. **提炼**：一句话结论 + 化简后的核心问题 + 3–5 个「值得做成交互的概念」（判断标准：能用一个可操作的画面让人豁然开朗）。
3. **写原稿**：按 writing.md 的范式写 Markdown；每个交互块必须写降级内容。
4. **选组件**：组件库里有的直接用；没有的写成文章专属组件（文件夹文章）。
5. **自检**：构建 → 浏览器检查桌面和手机 → 控制台零报错 → 凡不是原文的数字都标「示意」。
6. **导出**：生成 CSDN 版本，检查降级内容是否读得通。

skill 定的是「怎么想、守什么底线」，不规定每篇长什么样——每篇的首屏、组件、节奏都可以不同。

## 6. Phase 5 — 端到端验证

把本文（怪物骨骼动画）迁移成第一篇 `design: stage` 文章：
- 生成器构建出的页面与 design-lab 版本一致；
- 旧文章页面快照不变；
- 全部测试通过；
- 导出 CSDN 版本并人工通读；
- **不 push**，等你本地预览确认后再决定发布。

## 7. 风险与对策

| 风险 | 对策 |
|---|---|
| AI 写的专属组件质量参差 | 组件契约 + qa.md 自检清单 + 只在文件夹内生效，坏了不影响别的文章 |
| 动效过多影响阅读 | 动效预算写进 motion.md：每屏最多一个主动效，正文动效只播一次 |
| 旧文章被新逻辑误伤 | 新功能全部由 `design: stage` 开关控制 + 快照测试 |
| 公开仓库泄露草稿 | 草稿仍在 gitignore 的 `drafts/`；文章文件夹只有发布后才进 `content/` |
| CSP / 安全 | 组件只从站内路径加载，不引入第三方脚本 |

## 8. 执行顺序

Phase 0（你确认审美）→ Phase 1 + 2（一起做，TDD）→ Phase 3 → Phase 4 → Phase 5（你确认后再 push）。
